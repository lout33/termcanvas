# termcanvas jokes

20 jokes about managing agent fleets, stale terminals, context windows, handoffs, attention routing, and termcanvas itself. full lowercase, casual luis voice. the strongest 5 are marked with a star (*).

## one-liners

running 40 agents is easy. knowing which one stopped is the whole product. *

agent sync overwrote my terminal title. i called it "frontend". it became "worker-7". we are not the same.

close the app: detach. close the node: destroy. close your laptop: pray. *

six seconds to discover a child agent. my actual child responds faster. barely.

the resize observer fired 47 times on one drag. the terminal was always going to be 636x414.

terminalId, sessionKey, tmux session, agent name. four names for the same shell. i have one name and still get it wrong.

ask is blocking rpc. so am i, when someone asks me to do something and then watches.

## observations

agentmux marks an agent stale after 15 minutes. 15 minutes. that's not stale, that's a coffee break. my agent is just thinking. *

the attention queue says "2 agents need input." two of my last three jobs had the same problem and no queue.

we removed the commander/worker tree so everyone's a peer. the graph got friendlier. the work didn't change.

an agent read 40 files into context, then asked me what the project does. the files were right there. it read them. *

there are orphan tmux sessions on this machine from three weeks ago. they have names. i don't remember naming them. they're still running. somewhere. *

we ran an experiment asking "is the spatial canvas necessary." the honest answer was "depends who you ask at 2am."

webgl rendering got unstable with many terminals so we pause hidden ones. they're still thinking. we just stopped watching.

the attention layer is just my phone notifications but for things that actually matter to my code.

spawn lineage is the ownership structure. so when my agent's child fails, that's... my problem apparently.

an agent with a 200k context window forgot what it was doing in the first 10k. not a memory problem. a priorities problem.
